# 06 — 全面审计与优化计划

状态：**P0 代码/数学/视口回归已完成；真人试玩仍待完成**
审计日期：2026-08-08（视口回归与 m3/m5/m7/m8 证据登记于同日补完）
审计对象：`main` / 后续 polish 分支（十二关历史战役版）

## 1. 结论

当前版本已经具备一套可靠的战棋技术底座：确定性规则、窄随机伤害、连续花名册、重放、批量模拟、十二关历史档案以及统一的地图/人物资产。它已经能被称为“可验证的历史战棋纵向切片”，但还没有达到《三国志曹操传》《决战朝鲜》那种完整 SRPG 的决策厚度。

本轮优先级不是继续堆叠美术或数值，而是先修复四类会让玩家失去信任的问题：

1. **资料、显示与实际规则不一致**：将领属性双计、敌我职务混用、装备名称与机械型号不一致、部分任务与新史料档案冲突。
2. **行动前不可判断**：点击敌军立即提交攻击，没有预计伤害、反击与主要修正，也没有结束回合保护。
3. **行动后不可解释**：规则已经生成伤害拆解与战斗日志，但界面没有渲染。
4. **“门槛通过”掩盖局部失衡**：现有报告允许 M10 被多种退化打法以接近 100% 胜率统治，CI 的平衡步骤也不会阻断合并。

因此，本轮采用“先修真相 → 再修决策反馈 → 重建平衡基线”的顺序。弹药、工事、技能树、军械数量等高风险系统进入下一阶段，不与底板修复同时上线。

## 3. 经典对标：学习什么、不照搬什么

### 3.1 《三国志曹操传》

最值得借鉴的是“第二层目标”和可逆操作链：

- 移动后先进入行动菜单，玩家可以比较攻击、道具、待命，再确认不可逆动作。
- 攻击前能理解伤害、反击与地形，而不是点击后才知道代价。
- 宝物、人物存活、接触事件和路线选择让一张地图同时存在通关、角色、收集与剧情目标。
- 战后明确展示升级、装备和人物去留，使长期角色具有情感价值。

本项目不照搬高命中随机、暴击或练果。当前 `[0.92, 1.08]` 的窄随机、无命中判定和可解释伤害是现代化优势，应保留。

### 3.2 《决战朝鲜》

最值得借鉴的是“后勤和阵地也是玩法”：

- 弹药、补给、运输与换武器形成持续作战选择。
- 工事、地雷、预备队、炮击和疏散让阵地选择具有时间维度。
- 同一单位会根据步兵、装甲和面目标选择不同武器，而不是只选择总评分最高的装备。
- 历史天气与火力条件会改变行动计划，而不只是简报文案。

本轮不立即全量引入弹药/工事，因为将领底板与关卡门槛尚未清洁。P1 只在 M2、M4、M9、M10 做有限试点，验证后再决定是否推广十二关。

## 5. 本轮实施包

### 5.1 数据与历史真相

- 修复伴随将领绝对底板解释。
- 新增缺失的联合国军装备数据，并由装备名称解析机械型号。
- 关闭会改变装备类别的旧式 `variantSlots`；以后使用完整编成变体替代单独改兵种。
- 将高大全的固定战时职务与 Lv. 分开显示；敌军普通分队不套用志愿军职务。
- 修正已确认的逐关硬错误；高大全跨战区连续成长明确为“历史战役选集的虚构叙事连接”，不宣称真实行程。
- 主角被击溃的叙事统一为“重伤、任务失败”，不再一边写“战役无法继续”一边推进下一关。

### 5.2 决策与反馈

- 攻击预测显示：伤害范围、目标剩余生命、是否/可能反击、反击范围、主要倍率。
- 预测由与结算同源的 `damageComponents` 生成，不另写一套公式。
- 最近交火面板显示实际伤害、反击和主要因素；战斗记录显示最近事件。
- 结束回合显示未行动单位数，支持二次确认和“下一支未行动单位”。
- 目标条显示短进度；修复道具槽、键盘范围、焦点、对比度、移动端底部面板和 `aria-live`。

### 5.3 平衡与验证

实施顺序必须固定：

1. 记录修复前 200 seeds 基线。
2. 修复属性/装备/任务后运行单测和小样本模拟，先找方向性崩溃。
3. 只通过 `src/content/balance.ts`、关卡兵力/回合/目标调参恢复目标带；既有主力护卫减伤必须在单位卡与伤害拆解中明确显示，不允许不可见特权。
4. 运行正式 200 seeds、连续战役与退化策略。
5. 报告和 PRD 同步后，CI 才启用阻断。

新的自动门槛：

| 门槛 | 目标 |
|---|---|
| 随机策略 | 每关 < 15% |
| 基础策略 | 分关带内；十二关平均任务完成率 25–65%（靶心 40%） |
| 战术策略 | 每关 > 52%，且伤亡上限仍受约束 |
| 局部退化打法 | 任一退化策略不得在单关达到 85% 以上；若史实坚守关必须例外，应逐关书面说明而不是放宽全局 |
| 不可完成种子 | 策略库不得发现全策略均失败的种子；报告措辞不得声称数学证明 |
| 恢复能力 | 第一关重创后第三关仍可恢复，进入第三关编制不少于 3 |
| CI | 类型检查、单测、构建、平衡 smoke 任一失败均阻断 |

## 6. 本轮不做

- 不一次性加入弹药、工事、技能树和 LOS；它们会同时改变 AI、地图和十二关平衡。
- 不把历史军级/集团军级将领变成前线单格作战单位。
- 不以“史实”为理由制造必中、必败或全图不可反制伤害。
- 不为填满卡片而伪造军衔、精确坐标、单位番号或装备。
- 不用模拟 Agent 代替真人可用性测试。

- 点击攻击目标不会立即结算；预测后确认/取消均正确。
- 预测的伤害上下界覆盖实际伤害，反击条件与核心规则一致。
- 有未行动单位时第一次结束回合不推进回合。
- 7 种正库存道具全部可见。
- HUD 所有非空间目标都不会表现成无效定位按钮。
- 战斗通知和最近交火对辅助技术可读。
- 390×844、844×390、1366×768 三档检查无遮挡、无裁切、可完成主流程。

### 真人验证（材料就绪 / 等待真人场次）

清单与脚本：[`playtest-checklist.md`](./playtest-checklist.md)。

至少 5 名首次玩家，每人完成 M1–M3；其中 2 人继续到 M7。记录：

1. 第一次移动/攻击是否需要口头提示。
2. 是否在攻击前阅读预测，是否能解释一次意外高/低伤害。
3. 是否发生误结束回合、误用道具或找不到未行动单位。
4. 是否主动保护高大全和高经验同伴。
5. 是否能说出至少两种有效打法。

## 8. 发布判定

本轮只能在以下条件同时满足时宣告完成：

- P0 数据和交互项已实现并有回归测试。
- 200 seeds 正式报告全部门槛通过，或例外被明确记录为已知阻断项。
- PRD 不再把未渲染/未验证能力标为已完成。
- 能完成代码级构建验证。
- 若浏览器截图环境不可用，必须明确写“视觉回归未完成”，不得把构建成功等同于视觉验收。
