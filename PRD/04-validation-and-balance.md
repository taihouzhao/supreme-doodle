# 04 — 验证与平衡

当前版本必须同时通过数学验证与真人验证。

## 数学验证

同一关卡由三类模拟玩家在大量种子上反复运行：

| Agent | 行为 |
|-------|------|
| random | 在合法动作中随机选择 |
| basic | 朝目标推进，攻击相邻最弱敌人 |
| tactical | 考虑地形、集火、机枪架设、曲射反制、残血后撤、道具时机、兵种克制 |

### 自动门槛

实现于 `src/sim/gates.ts`，任一条不满足即视为平衡不通过。

| 门槛 | 判据 |
|------|------|
| 能力梯度存在 | random 各关胜率 < 15%；basic 落在分关难度带；tactical 各关 > 75% |
| 难度曲线存在 | 至少 4 关不能被 basic 稳定碾压 |
| 技术控制伤亡 | tactical 各关平均伤亡不高于 basic 的 115% |
| 无不可能种子 | 每个种子至少有一种策略可完成核心目标 |
| 随机不主导 | 同策略跨种子胜率标准差有上限；单次抖动 / 援军时间不能反转结果 |
| 无统治性策略 | 退化打法（全员龟缩高地、无脑直推、单一兵种堆叠）无法稳定通关 |
| 无隐性死档 | 第一关重创后，第三关早期恢复检查仍有可行解；十二关战役平均任务胜率处于 55–85% |

### 报告内容

`reports/balance.md` 至少包含：各关 × 各策略的胜率、平均伤亡、平均回合数、胜率标准差、战役续跑恢复能力，以及门槛逐条通过情况。

## 真人验证

观察四件事：

1. 新玩家是否**不看说明**就能完成第一次移动和攻击。
2. 玩家是否能**解释失败原因**（界面需展示伤害构成）。
3. 玩家是否感受到**至少两种有效打法**。
4. 到第七关和中后段时，玩家是否**主动保护高大全与高经验单位**。

第 4 项最关键。如果玩家仍把所有单位视为可随意牺牲的棋子，即便单场战斗好玩，连续战役的核心也尚未成立。

## 失败时的处置

| 症状 | 处置 |
|------|------|
| 公平性不成立 | 重做规则与随机模型 |
| 公平但不好玩 | 重做任务与地图 |
| 单场好玩但玩家不在意老兵 | 重做战役继承与伤亡机制 |
