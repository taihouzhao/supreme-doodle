我需要做一个类似决战朝鲜的游戏
我会把第一版定义成一个**“可验证的战棋纵向切片”**，而不是完整复刻《决战朝鲜》。

## 第一版目标

第一版只验证三个核心假设：

1. **极简棋盘也能成立**  
   不依赖美术和特效，仅靠兵种、地形、任务和战斗结果，玩家仍然愿意完成一场战斗。

2. **决策比随机更重要**  
   玩家失败时能理解自己为什么失败；水平更高的玩家应明显拥有更高胜率、更低伤亡，而不是依赖刷随机数。

3. **连续战役能让玩家在意部队**  
   打完三场连续战斗后，玩家开始把高等级单位视为长期资产，而不是一次性棋子。

第一版真正需要证明的不是“能不能做出战棋”，而是：

> **玩家是否愿意为了保存一支老部队，改变当前这一关的打法。**

## 第一版产品范围

做一个支持电脑和手机浏览器的单人网页游戏，鼠标和触屏采用相同的“点击单位—点击目标”操作。

内容只做一个小章节，包含三场连续任务：

- 突破或占领；
- 阻击或坚守；
- 撤退、护送或保存主力。

三场战斗之间继承部队状态，包括生命、经验、疲劳和少量物资。

兵种、地形和道具使用玩家天然能够理解的概念，例如步兵、机枪、迫击炮、坦克、高地、森林、村庄、医疗包、反坦克武器和炮火支援。第一版不追求兵种多，而追求每一种兵种都有明确用途。

随机性只出现在受约束的范围内：

- 敌军组合略有变化；
- 援军可能在一个小时间窗口内出现；
- 天气、道具和支线目标存在变化；
- 核心任务、关键道路和玩家初始兵力保持稳定。

也就是说，随机性负责制造变化和代价，不负责决定玩家能不能通关。

第一版不做多人对战、账号体系、复杂装备树、大规模随机地图、长剧情演出和完整历史复刻。可以借用《决战朝鲜》的认知模型，但不直接复制原作素材、文本或具体关卡。

## 验证标准

第一版完成后，需要同时通过“数学验证”和“真人验证”。

数学验证方面，同一个关卡至少由三类模拟玩家反复运行：

- 随机行动；
- 基础策略；
- 战术策略。

理想结果应该呈现明显的能力梯度，例如随机玩家很难胜利，基础策略大约有一半胜率，战术策略能够稳定获胜并显著降低伤亡。

同时必须满足：

- 不存在无法完成核心目标的随机种子；
- 不存在明显的无脑统治性策略；
- 同一合理策略在不同种子下，胜负不会剧烈反转；
- 单次暴击、掉落或援军时间不能直接决定整场胜负；
- 三场连续战斗中，即使前一场发生较大损失，后续仍有恢复空间，不形成隐性死档。

真人验证方面，重点观察四件事：

- 新玩家是否不看说明也能完成第一次移动和攻击；
- 玩家是否能解释失败原因；
- 玩家是否感受到至少两种有效打法；
- 到第三关时，玩家是否开始主动保护某个高经验单位。

最后一项尤其重要。如果玩家仍然把所有单位当作可随意牺牲的棋子，那么即使单场战斗很好玩，连续战役的核心也还没有成立。

## 基础架构

架构只保留四个部分：

**规则核心**

使用纯 TypeScript 实现确定性的规则引擎。输入是当前状态和玩家动作，输出是新的状态与事件：

```text
GameState + Action + Seed
→ NewGameState + Events
```

规则核心不依赖网页界面。移动、攻击、地形、任务、道具、随机数和战役继承都在这里统一计算。

**内容配置**

兵种、地形、道具和关卡全部通过配置描述，而不是写死在代码中。这样后续可以快速修改数值、增加任务，也便于模拟器自动生成不同配置进行测试。

**网页表现**

网页只负责显示棋盘、接收点击和播放规则核心返回的事件。手机使用底部单位面板，电脑使用侧边面板，但操作逻辑完全一致。

**模拟与回放**

AI Agent 和蒙特卡洛模拟器直接调用同一个规则核心。每局保存初始状态、随机种子和玩家动作，因此任何一局都可以完整重放，也可以准确复现异常结果。

整体关系是：

```text
                 规则核心
              /     |      \
          网页UI   AI玩家   模拟器
                     |
                  平衡报告
```

第一版不需要复杂后端。存档、设置和回放可以先保存在浏览器本地；只有需要跨设备存档或收集测试数据时，再增加轻量服务。

## 第一版交付物

第一版最终应交付四样东西：

1. 一个手机和电脑都能玩的网页版本；
2. 一个包含三场连续任务的小章节；
3. 一个可以批量运行关卡的模拟器；
4. 一份平衡报告，说明不同策略的胜率、伤亡、回合数、随机波动和战役恢复能力。

第一版通过以后，才进入下一阶段：扩展到约十场任务、加入更完整的剧情分支和部队成长。

判断标准也很明确：

- **公平性不成立**：重做规则和随机模型；
- **公平性成立但不好玩**：重做任务和地图；
- **单场好玩但玩家不在意高等级单位**：重做战役继承和伤亡机制；
- **三者都成立**：这个游戏的核心产品假设基本得到验证。
