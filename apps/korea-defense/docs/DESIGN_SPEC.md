# 决战朝鲜：塔防 2D 重设计规范

版本：0.1
状态：已实现；默认“雪夜手绘”方向线上验证通过（commit `019f523`）；三张方向板为后续最终美术精修门
日期：2026-08-15
关联计划：[REDESIGN_PLAN.md](./REDESIGN_PLAN.md)

## 1. 产品体验定义

### 1.1 一句话体验

玩家像在雪夜指挥所摊开一张实时作战图：快速识别敌军沿北线公路推进的方向，在有限阵地上部署步兵、机枪和迫击炮，守住温井指挥所。

### 1.2 设计原则

1. **先读战况，再看装饰。** 路线、敌我、射程、危险和主操作永远高于纹理氛围。
2. **像作战图，不像积木沙盘。** 俯视纹理、等高线、手绘标记和单位牌构成空间，不使用玩具式低模。
3. **历史氛围不冒充历史复原。** 保留明确的玩法改编说明，不增加未经核实的史实描述。
4. **形状与文字双编码。** 阵营、兵种、等级、危险状态不能只靠颜色。
5. **移动端不是缩小桌面。** 竖屏重新排列信息与操作，地图仍是第一视觉焦点。

## 2. 视觉方向：雪夜战术作战图

### 2.1 气质

- 冷、克制、低饱和；雪地与夜色形成主要明暗对比。
- 地图是带磨损边缘的军用作战图，不使用厚重拟物面板。
- 单位以俯视 Sprite + 战术符号底牌表达，避免过小的人物细节。
- 关键反馈使用短促、高对比的战术标记，不使用大面积霓虹光效。

### 2.2 禁止项

- 不再使用方块敌军、圆锥炮塔、圆柱节点作为最终视觉。
- 不使用 emoji、文字符号或 CSS 几何假装单位美术。
- 不用纯红/纯绿作为唯一阵营区分。
- 不给每个敌军常驻大号生命条；只在受损、悬停/选中或高威胁时显示。
- 不使用连续全屏雪花、模糊和暗角遮挡路线。

## 3. 信息层级

战斗中视觉优先级从高到低：

1. 当前危险：敌军位置、推进方向、接近指挥所的单位。
2. 当前决策：选中节点/单位、射程、部署成本、升级或撤回。
3. 战局状态：指挥所完整度、波次、部署点、暂停/倍速。
4. 地形意义：道路、森林、高地、河流、支路。
5. 氛围：雪地纹理、地图磨损、烟尘和轻量天气。

任何低层级内容不得遮挡更高层级内容。

## 4. 页面与布局

### 4.1 首页 / 作战简报

结构顺序：

1. 阵营标识、游戏名、任务副标题。
2. 温井防御战简报：时间、天气、入口方向、玩法改编说明。
3. 普通/困难模式卡；锁定状态必须同时有图标、文字和 disabled 属性。
4. 军械库：步兵、机枪、迫击炮等级与升级成本。
5. 设置：画质、音效、音量。

视觉：宽屏使用左侧简报、右侧模式/军械库；窄屏按上述顺序单列。首页背景可以使用一张低对比地图裁切图，但文本区域必须有稳定实色底。

### 4.2 战场

| 视口 | 地图 | 控制区 | 关键约束 |
| --- | --- | --- | --- |
| ≥1024 px | 占剩余宽度 | 320–340 px 右栏 | 地图是首要面积；右栏内部滚动 |
| 700–1023 px 横屏 | 占剩余宽度 | 280–300 px 右栏 | 一屏可见开始波次、暂停和倍速 |
| <700 px 竖屏 | 42–50dvh 顶部 | 底部控制托盘 | 主操作 sticky；单位卡横向三列 |
| 320–389 px | 至少 250 px 高 | 单列紧凑控制 | 不隐藏指挥所完整度与当前波次 |

战场内只放地图相关信息：北向、入口、指挥所、路线、部署点、射程和单位。部署成本、升级/撤回、暂停和倍速保留在 DOM 控制区。

### 4.3 顶部状态栏

- 左：任务名与模式。
- 中：指挥所完整度、部署点、当前波次。
- 右：时间和返回。
- 竖屏可隐藏任务副标题和时间，但不得隐藏完整度、部署点和波次。
- 完整度同时使用数字、短标签和进度条；低于 30% 时加入警告图标及脉冲边框，遵守 reduced-motion。

### 4.4 教学

- 第一次进入仍为四步：选择阵地 → 选择部队 → 升级 → 开始波次。
- 桌面使用锚定到目标区域的提示卡；移动端使用底部说明条。
- 每步只高亮一个目标，其余区域降低对比但不完全遮挡地图。
- 保留“跳过教学”；教学文案存在于 DOM，不绘制进 Canvas。

### 4.5 结算

- 胜负图标、结果、完整度、用时、击杀/突破、星级和主要返回按钮。
- 胜利与失败不只通过颜色区分，使用不同图标、标题和边框形状。
- 结果弹层宽度不超过 440 px；320 px 视口保持 16 px 外边距。

## 5. 战场坐标与相机

### 5.1 世界坐标

- 核心仍使用 22×14 网格和现有浮点路径坐标。
- 渲染逻辑 tile：64×64 世界像素；完整地图为 1408×896 世界像素。
- 所有单位位置、路径、部署点和射程统一通过 `worldToScreen()` 转换。
- 不允许在各绘制函数中重复实现缩放或偏移公式。

### 5.2 Canvas 尺寸

- CSS 尺寸来自容器。
- backing store = CSS 尺寸 × effective DPR。
- 高画质 DPR 上限 2；低画质 DPR 固定 1。
- 每次 resize 后重置 transform，再应用相机 transform，防止累乘误差。

### 5.3 相机

- 初次进入自动 fit 全图，并保证北侧入口和南侧指挥所可见。
- 桌面缩放范围 0.75–2.25；移动端 0.85–2.0。
- 平移限制保留至少 15% 地图在视口内，不能把地图完全拖走。
- 滚轮围绕指针缩放；触控首版支持单指拖动，双指缩放在 P4 完成。
- 点击与拖动阈值：移动距离 <8 CSS px 且持续时间 <350 ms 视为点击。

## 6. 绘制层级

严格按以下顺序绘制：

| 层 | 内容 | 更新频率 |
| --- | --- | --- |
| 0 | 战场外深色背景 | resize |
| 1 | 雪地底图、河流、森林、高地、道路 | 任务或质量变化 |
| 2 | 等高线、网格、地图边缘、方向标 | 任务或质量变化 |
| 3 | 敌军主路线、困难支路、入口、指挥所 | 任务或模式变化 |
| 4 | 部署点及可用/占用/不可用状态 | 选择或部署变化 |
| 5 | 选中范围、最小射程、目标指示 | 选择或目标变化 |
| 6 | 友军单位、等级、朝向 | snapshot tick |
| 7 | 敌军单位、受损状态、生命值 | snapshot tick |
| 8 | 弹道、爆炸、命中、突破 | animation frame |
| 9 | 地图内标签与局部警告 | 状态变化 |

层 1–3 合成为静态缓存 Canvas。相机移动时把缓存作为一张图绘制，不逐 tile 重建。首版使用普通隐藏 Canvas；只有性能证据表明主线程缓存是瓶颈时才引入 OffscreenCanvas。

## 7. 地形与战术标记

### 7.1 地形

- `plain`：低对比雪地底纹，避免纯白。
- `road`：使用现有 `road-snow.png`；路线中心增加细虚线，不能盖住单位。
- `forest`：使用现有 `forest-snow.png`；边缘做不规则遮罩，不能形成完整方格感。
- `hill`：使用现有 `hill-snow.png`；等高线明确，取消真实 3D 抬升。
- `river`：冷灰蓝，使用岸线双描边；不与道路使用相似亮度。
- `command`：在地形上叠加指挥所实体与防区轮廓，不改变核心格属性。

允许对现有 128×128 纹理做旋转/镜像变体，减少重复感；不拉伸、不改变像素宽高比。

### 7.2 路线

- 主路线：灰白道路底 + 暗边 + 稀疏方向箭头。
- 困难支路：在未解锁时不显示；困难模式使用不同虚线节奏，而非仅换色。
- 当前危险段：根据敌军距指挥所的最小剩余距离，最多突出一段，避免全路闪烁。

### 7.3 部署点

- 可用：黄铜色六边战术标记，视觉尺寸 24–30 px。
- 选中：外圈 2 px + 四角定位线，低速呼吸；reduced-motion 下保持静态。
- 已占用：显示兵种底牌与等级，不再显示空节点中心。
- 命中区域：至少 44×44 CSS px，与可见图形尺寸分离。
- Canvas 点击之外，DOM 节点列表始终提供等价选择路径。

## 8. 单位规范

### 8.1 友军

共同结构：带方向的绿色/蓝灰战术底牌 + 俯视 Sprite + 兵种符号 + 等级短杠。

| 类型 | 轮廓 | 关键识别 | 攻击反馈 |
| --- | --- | --- | --- |
| 步兵班 | 圆角菱形 | 步枪斜线符号 | 短白黄曳光 |
| 机枪阵地 | 横向六边形 | 双脚架/连续点符号 | 高频短曳光、轻量枪口闪光 |
| 迫击炮组 | 圆形阵地 | 炮管与弧线符号 | 抛物线提示 + 落点圆环 |

- 1/2/3 级使用 1/2/3 条短杠，不只改变亮度。
- 选中后显示单位名、等级、范围；未选中时不显示常驻文字。
- 迫击炮同时绘制最大射程和内侧最小射程；两个区域使用不同线型。

### 8.2 敌军

共同结构：砖红/暗赭底牌 + 白灰敌军 Sprite；底牌尖角朝向移动方向。

| 类型 | 大小 | 轮廓 | 关键识别 |
| --- | --- | --- | --- |
| rifle | 32 px | 窄菱形 | 单步枪符号 |
| runner | 28 px | 前倾箭头 | 双短线速度标记 |
| heavy | 38 px | 宽盾形 | 厚边与重装符号 |
| armored | 46 px | 长矩形 | 履带/车辆轮廓 |

- 当前 HP <100% 时显示 2–3 px 生命条；满血不显示。
- 距指挥所最近的高威胁单位增加静态警告角标；不使用持续缩放。
- 单位重叠时按 y 坐标排序，并给同一路段单位加入最多 ±4 px 的视觉横向偏移；不得修改模拟坐标。

## 9. 战斗效果

- 步兵/机枪弹道：80–140 ms，线宽不超过 2 px。
- 迫击炮飞行：以视觉曲线表现，真实伤害时点仍由 snapshot 决定。
- 命中：小型放射线或雪尘，120–240 ms。
- 爆炸：中心亮点、暗烟和范围环三段，300–450 ms；低画质取消烟层。
- 突破：指挥所边框一次短闪，顶部完整度更新并播报；不做全屏红闪。
- 暂停：单位与特效停止，地图上方显示明确“已暂停”，不能只改变按钮文字。

`prefers-reduced-motion: reduce` 时：取消呼吸、抖动、路径流动和屏幕闪动；保留即时状态切换。

## 10. 色彩与字体

### 10.1 语义色板

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--ink-950` | `#111916` | 页面背景、最深描边 |
| `--pine-900` | `#1B2C27` | 控制面板 |
| `--pine-700` | `#385247` | 次级面板、友军暗部 |
| `--snow-100` | `#E4E4DC` | 主文字、雪地高光 |
| `--snow-300` | `#BEC3BB` | 次级文字、地图线 |
| `--brass-500` | `#C7A65A` | 部署点、主要操作 |
| `--ally-500` | `#557A68` | 友军底牌 |
| `--enemy-500` | `#A95349` | 敌军底牌 |
| `--river-500` | `#567588` | 河流 |
| `--warning-500` | `#D9775E` | 危险与完整度警告 |

最终色值必须在方向板后用真实截图校准。正文和按钮文字以 WCAG 2.2 AA 对比度检查为发布门；地图单位同时用形状、描边和图标补充颜色。

### 10.2 字体

- 标题：系统宋体栈 `Songti SC, STSong, Noto Serif SC, serif`，仅用于任务名和大标题。
- UI 与数字：现有系统无衬线栈；数字使用 `font-variant-numeric: tabular-nums`。
- 首版不增加远端字体请求，避免首屏阻塞与跨域依赖。
- 最小正文 12 px；关键状态与按钮至少 14 px；320 px 视口不缩到不可读。

## 11. 资源规范

### 11.1 复用

- 直接复用：三张雪地地形纹理、阵营标识、天气图标、胜负图标、兵种 SVG。
- 兵种 SVG 可作为 HUD 图标；战场单位不得直接把 HUD 图标放大冒充最终 Sprite。

### 11.2 新增资源清单

- 友军：3 类型 × 3 等级，允许等级通过统一标记叠加，避免 9 套重复图。
- 敌军：rifle、runner、heavy、armored 四类俯视 Sprite。
- 设施：指挥所、敌军入口、空部署点。
- 效果：枪口、曳光、迫击炮弹、三档爆炸、雪尘、突破警告。
- UI：暂停、倍速、锁定、危险、方向、升级和撤回图标，优先使用同一现有图标库。

### 11.3 文件要求

- 透明单位资源优先 WebP 或 PNG；需要无损边缘时保留 PNG。
- 单位源文件建议 96×96 或 128×128，运行时按 28–48 CSS px 绘制。
- 文件名使用小写 kebab-case，并按 `terrain/`、`units/ally/`、`units/enemy/`、`effects/`、`ui/` 分类。
- 所有新增素材在 `public/assets/SOURCES.md` 记录来源、授权和用途。
- 不在运行时依赖外站素材或 CDN。

## 12. 交互与可访问性

- 所有按钮和等价地图目标至少 44×44 CSS px；这是项目内部标准，高于 WCAG 2.2 AA 的 24×24 最低门槛。
- 拖动平移不是唯一方式：提供“回到全图”按钮；部署可通过 DOM 节点列表完成。
- 键盘：Tab 遍历控制；Enter/Space 激活；Escape 清除选择；`+`/`-` 缩放；`0` 回到全图。
- 焦点环 2 px，和背景保持明显对比，不被 `overflow` 裁切。
- `aria-live="polite"` 播报波次开始、资源不足、部署成功、升级和指挥所受损；连续击杀不逐条播报。
- Canvas 提供可理解的 `aria-label`；具体交互仍有 DOM 等价控件。
- 高危信息同时使用颜色、形状和文字。

## 13. 技术接口

建议接口：

```ts
export interface PresentationState {
  selectedNodeId: string | null;
  selectedTowerId: string | null;
  selectedTowerType: TowerType;
  mode: DefenseMode;
  quality: "high" | "low";
  reducedMotion: boolean;
}

export interface RendererDiagnostics {
  renderer: "three" | "canvas2d";
  staticCacheBuilds: number;
  loadedAssets: number;
  failedAssets: string[];
  activeVisuals: number;
}

export interface DefenseRenderer {
  render(snapshot: SimulationSnapshot, presentation: PresentationState): void;
  resize(): void;
  resetCamera(): void;
  diagnostics(): RendererDiagnostics;
  dispose(): void;
}
```

约束：

- Renderer 不得 import `engine.ts` 的可变状态或调用 `dispatchCommand()`。
- Renderer 不得修改 snapshot、关卡配置或 RNG。
- 地图点击只返回 `nodeId`/`towerId`，由 app 决定命令。
- 素材失败必须进入 diagnostics，并展示可读错误；不得静默空白。
- `dispose()` 必须移除监听器、断开 `ResizeObserver`、释放缓存 Canvas 引用并清空宿主节点。

## 14. 性能预算

| 指标 | 目标 | 硬门 |
| --- | --- | --- |
| 战斗帧率 | 60 FPS | 三个目标视口均 ≥30 FPS |
| JS gzip | ≤100 KiB | 例外必须附构成分析 |
| DPR | 高画质 ≤2 | 低画质 =1 |
| 静态地图重建 | 任务/质量/resize 时 | 普通 tick 不重建 |
| 敌军 | 当前 64 上限 | 不丢单位、不溢出数组 |
| 特效 | 当前 48+48 槽位 | 超限丢弃最旧视觉，不影响伤害 |
| 重置稳定性 | 10 次进出一致 | 监听器、Canvas 和缓存不增长 |

实现规则：

- 每帧不调用 `getImageData()`。
- 避免为每个单位创建 DOM 节点。
- 资源预解码完成前不进入任务；失败时给出重试/返回，不显示无限 loading。
- 页面暂停或 snapshot/动画均无变化时允许跳过绘制。
- 只有实测主线程静态缓存成为瓶颈，才升级为 OffscreenCanvas/Worker。

## 15. 状态与故障设计

必须定义并测试：

- `loading-assets`：显示实际进度或明确“正在准备战场”，5 秒后显示重试建议。
- `ready`：任务可进入。
- `asset-failed`：列出失败类别并允许重试/返回；不无限旋转。
- `playing`、`paused`、`won`、`lost`。
- `canvas-unavailable`：核心页面仍可返回首页，说明浏览器无法创建 2D 画布。
- `resized`、`orientation-changed`：相机保持有效范围，不丢失当前选择。
- `backgrounded`：恢复后不瞬间补算大量视觉帧；核心仍遵循现有 elapsed 上限。

## 16. 验收场景

每个目标视口至少捕获以下状态：

1. 首页：普通可用、困难锁定、军械库可见。
2. 战前：全图、入口、路线、指挥所和七个部署点可识别。
3. 选择空节点：步兵预览、成本和射程可见。
4. 选择迫击炮：最大/最小射程可区分。
5. 第三波进行中：至少三类敌军、弹道、受损和危险段可见。
6. 暂停：地图和 DOM 都明确暂停。
7. 胜利与失败：两种结果信息完整。
8. 资源加载失败：没有无限 loading，可重试或返回。

功能 smoke：

- 首次教学四步及跳过。
- 地图选择和 DOM 节点列表选择一致。
- 部署、升级、撤回、开始下一波、暂停、1×/2×。
- 高/低画质设置持久化。
- 10 次首页/任务切换无残留 Canvas 和监听器增长。
- 390×844 与 844×390 无横向溢出；主要操作不被浏览器安全区遮挡。
- 固定 seed 的最终完整度、用时、击杀、突破和星级与迁移前一致。

## 17. 视觉评审门

本轮可玩版本已按第 2 个方向“雪夜手绘”落地；以下三张方向板是后续最终美术精修的评审门，不阻塞当前功能验收。

P0 必须提供恰好三张同状态方向板供选择：

1. **军用地图**：最克制、信息密度最高、纹理最轻。
2. **雪夜手绘**：复用现有雪地纹理，加入手绘边缘与单位 Sprite；默认推荐。
3. **档案插画**：纸张与档案感最强，UI 更具叙事性，但地图装饰风险最高。

三张图必须使用相同网格、相同单位位置和相同 HUD 内容，禁止用不同玩法状态掩盖设计差异。选中后才冻结色板、单位形状和最终资源清单。
