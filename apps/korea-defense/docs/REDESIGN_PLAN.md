# 决战朝鲜：塔防视觉重设计计划

状态：Implemented locally；release verification pending
日期：2026-08-15
范围：`@dashjie/korea-defense` 温井防御战垂直切片
关联规范：[DESIGN_SPEC.md](./DESIGN_SPEC.md)

执行方向：按用户“按照计划执行”的确认，采用默认推荐的“雪夜手绘”方向；三张方向板保留为后续最终美术精修门，不阻塞本轮可玩版本。

## 1. 结论

将战场从“Three.js 程序化低模”迁移为“Canvas 2D 雪夜战术作战图”，保留现有模拟、数值、存档和音效。DOM/SVG 继续承载 HUD、部署面板、教学和结算。

迁移不一次性删除 Three.js。先建立渲染器边界和 Canvas A/B 版本，在相同 `SimulationSnapshot` 下完成玩法等价、视觉评审、三视口性能和远端验证，再删除 Three.js 依赖。

## 2. 为什么现在重设计

当前战场在 `src/client/scene.ts` 中使用方块地形、圆柱部署点、圆锥炮塔、方块敌军和简单光照，而首页与控制区使用平面 SVG/PNG。两套视觉语言没有形成统一风格。

仓库已经包含 `road-snow.png`、`forest-snow.png`、`hill-snow.png` 等俯视雪地纹理；原实现没有使用。继续给程序化几何增加模型、材质、灯光和后期处理，会扩大资源制作与 WebGL 生命周期成本，却不直接提升战术信息可读性。

当前可量化基线：

- 战场逻辑网格：22 × 14。
- 峰值容量：64 个敌军实例，48 个投射物和 48 个命中特效槽位。
- 当前主 JS：555,432 bytes，gzip 143,345 bytes。
- 当前验证视口：1366×768、844×390、390×844。
- 当前核心：20 Hz 固定步长；渲染只读取 `SimulationSnapshot`。

## 3. 目标与非目标

### 目标

- 形成统一的“1950 年冬季战术地图”视觉语言。
- 玩家在 1 秒内辨认敌军入口、主路线、指挥所、部署点和当前危险方向。
- 不依赖颜色也能区分阵营和单位类型。
- 桌面、手机横屏和手机竖屏保持完整玩法。
- 在现有测试设备与 CI 浏览器中维持 60 FPS 目标、30 FPS 硬门槛。
- 迁移过程不改玩法结果、RNG、波次、经济和存档结构。
- 删除 Three.js 后，降低首包脚本和 WebGL 故障面。

### 非目标

- 不制作真实 3D 地形、自由旋转镜头或透视相机。
- 不复刻历史战场的精确比例与胜负。
- 不扩充新关卡、兵种、波次或成长系统。
- 不在本轮重做音效系统。
- 不在视觉方向确认前批量制作最终美术。

## 4. 决策记录

| 决策 | 选择 | 原因 | 代价 |
| --- | --- | --- | --- |
| 战场渲染 | Canvas 2D | 适合俯视纹理、路线标记、单位 Sprite 和轻量特效 | 需要自行维护绘制顺序和命中测试 |
| UI 渲染 | DOM + SVG/PNG | 保留可访问性、响应式布局和现有控件 | Canvas 与 DOM 状态要保持同步 |
| 视觉方向 | 雪夜战术作战图 | 与现有雪地资产、历史题材和塔防信息密度一致 | 需要新增单位与战术标记素材 |
| 地图投影 | 正交俯视，轻量假高度 | 保证路线和射程可读 | 不提供真实遮挡与空间深度 |
| 迁移策略 | A/B 渲染器，后删 Three.js | 可比较、可回滚、不影响核心模拟 | 迁移期短暂维护两个渲染器 |
| 2D 引擎依赖 | 首版不引入 | 当前实体上限不要求额外框架 | 若实测性能不足再评估 PixiJS 等方案 |

## 5. 交付物

1. 三张视觉方向板：战前、战斗中、选中阵地；同一视口、同一战局状态。
2. `DefenseRenderer` 接口及现有 Three.js 适配器。
3. `CanvasDefenseScene` 与资源清单加载器。
4. 雪地静态地图、路线、指挥所、部署点和战术标记。
5. 友军、敌军、射程、弹道、命中、生命值和波次危险提示。
6. 首页、战场 HUD、部署区、教学和结算的统一视觉改版。
7. 更新后的单元测试、浏览器 smoke、截图基线和构建预算。
8. 删除 Three.js 依赖后的最终构建与 R2 线上验证记录。

## 6. 分阶段实施

### P0：视觉基线与方向门

产出：

- 固定普通模式 seed、初始部署和第一波状态，形成可重复截图场景。
- 以现有雪地纹理为基础制作三张方向板。
- 方向板必须同时展示地图、三类友军、四类敌军、部署点、射程和 HUD。
- 记录当前三视口截图与 JS gzip、FPS、资源请求基线。

退出条件：产品方向明确选中；没有选中方向前不制作最终 Sprite。

估算：0.5–1 工程日，另计美术迭代。

### P1：渲染器解耦

产出：

- 增加 `DefenseRenderer`、`RendererDiagnostics`、`PresentationState`。
- 将 `app.ts` 对 Three.js 具体类型的依赖改为接口依赖。
- 现有 Three.js 场景先通过适配器保持行为不变。
- 增加构建期渲染器开关，仅用于开发 A/B；生产仍指向旧渲染器。

退出条件：现有单元测试、浏览器 smoke、资源重置测试全部不退化。

估算：1 工程日。

### P2：Canvas 静态战场

产出：

- 资源 manifest、预加载与失败占位策略。
- 22×14 逻辑地图、世界/屏幕坐标转换、DPR 处理和相机约束。
- 静态缓存层：雪地、森林、高地、道路、河流、地图边缘和等高线。
- 战术层：北向、入口、路径、指挥所、部署点、困难模式支路。
- 鼠标拖动、滚轮缩放、触控拖动及点击/轻触命中测试。

退出条件：三个视口可以浏览完整地图；部署点可通过地图和 DOM 列表双路径选择。

估算：1–2 工程日。

### P3：单位、战斗与反馈

产出：

- 友军三类与 1–3 级状态。
- 敌军四类、朝向、受损状态和生命值表达。
- 射程/最小射程、目标连线、弹道、爆炸、命中和突破反馈。
- 选中、可部署、不可部署、升级、撤回、暂停和倍速视觉状态。
- 视觉插值只存在于表现层，不反写模拟状态。

退出条件：同一 seed 下，Canvas 与旧渲染器的部署、波次、胜负和结果数据完全一致。

估算：1.5–2.5 工程日，另计最终单位素材。

### P4：UI 与响应式重设计

产出：

- 首页改为“任务简报 + 模式 + 军械库”的作战档案结构。
- 桌面保持地图主导、右侧控制；横屏压缩控制区；竖屏使用地图 + 底部控制托盘。
- 战况、部署点、指挥所完整度、波次和主操作形成稳定优先级。
- 教学从全屏文字卡改为定位提示，但保留跳过和 DOM 可读文本。
- 键盘焦点、状态播报、降低动态效果和触控尺寸符合规范。

退出条件：三视口无关键遮挡、无横向溢出、所有主要操作目标至少 44×44 CSS px。

估算：1–2 工程日。

### P5：切换、清理与验证

产出：

- 默认切换为 Canvas，保留一个发布周期的开发回退开关。
- 更新 smoke：移除 WebGL context loss；增加资源失败、Canvas context、重置稳定性和截图回归。
- 达到性能与视觉门后删除 `three`、`@types/three`、WebGL 提示和相关测试。
- 更新 README、资源来源、部署说明和构建预算。
- 完整验证后 commit、push，等待 R2 workflow 完成，再验证规范 URL。

退出条件：见第 8 节 Definition of Done。

估算：1–1.5 工程日。

总估算：6–9 工程日，不含自定义美术来回迭代。估算不是发布日期承诺。

## 7. 风险与控制

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 先写代码后定视觉 | 重做地图和 Sprite | P0 设为硬门，先评审三张同状态方向板 |
| Canvas 文本/图像在高 DPR 模糊 | 信息不可读 | 逻辑尺寸与 backing store 分离，DPR 上限 2，逐视口截图 |
| 手动命中测试偏差 | 点不到小部署点 | 世界坐标统一；可见标记与至少 44 px 命中区分离；保留 DOM 节点列表 |
| 大量全屏重绘 | 手机发热、掉帧 | 静态地图缓存；暂停和无变化时跳帧；低画质关闭非必要粒子 |
| 新素材加载失败 | 空白或隐形单位 | manifest 预加载、超时与清晰错误态；测试故障注入 |
| 两个渲染器行为漂移 | 难以比较 | 两者只读相同 snapshot；A/B 期短；Gate C 后立即删除旧实现 |
| 风格好看但战术不清楚 | 玩法体验退化 | 每个视觉评审状态必须包含路线、射程、危险方向和受损反馈 |

## 8. Definition of Done

只有同时满足以下条件才算重设计完成：

- 核心模拟、关卡配置、RNG、波次、经济、存档 schema 未发生未批准变化。
- 三张方向板获得明确选中结论，最终实现与选中方向逐视口对比通过。
- 1366×768、844×390、390×844 的核心流程截图无裁切、遮挡和文本溢出。
- 首次教学、部署、升级、撤回、开始波次、暂停、1×/2×、结算全部通过。
- 每类单位不依赖颜色即可区分；地图外 DOM 节点列表仍可完成部署。
- 移动视口实测目标 60 FPS、硬门槛 30 FPS；10 次进出战场无 Canvas/监听器增长。
- JS gzip 目标不高于 100 KiB；若未达到，必须给出构成分析并获得例外批准。
- `npm run typecheck`、`npm run test`、`npm run build`、`npm run test:defense` 全部完整退出成功。
- `three` 与 `@types/three` 已从 defense workspace 和 lockfile 移除。
- R2 workflow 成功；`https://korea-tactics.dashjie.net/korea-defense/` 返回 200、无脚本/资源失败、可完成一次真实部署操作。

## 9. 回滚策略

- P1–P4：开发开关可切回旧 Three.js 渲染器，不回滚核心模拟。
- P5 删除 Three.js 前保留最后一个可验证 commit。
- 线上发现阻断问题时，仅回滚渲染器选择与视觉资源，不回滚玩法数据或 profile。
- 不使用不可恢复的 Git 操作；回滚使用新 commit。

## 10. 官方依据
